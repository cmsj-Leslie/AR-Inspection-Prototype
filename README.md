# 现场巡检问题标注系统 (AR Inspection Prototype)

本项目为全栈 AR 现场巡检原型系统，打通 **Unity AR 真机放置标记与上报** → **Go 后端持久化与广播** → **React 网页管理端实时查看与状态流转** 完整闭环。

---

## 1. 技术栈与环境版本

| 端 | 技术栈 | 运行/开发版本 | 依赖与关键库 |
| :--- | :--- | :--- | :--- |
| **移动端 (Unity)** | Unity LTS, C#, AR Foundation | Unity 2022.3 LTS / Android 14+ | AR Foundation 5.1.4, ARCore XR Plugin 5.1.4, TextMeshPro 3.0.9 |
| **后端 (Go)** | Go (Golang) | Go 1.22+ (推荐 1.24+) | 原生 `net/http` 路由 (Go 1.22+), `modernc.org/sqlite` (纯 Go，免 CGO) |
| **管理端 (React)** | React, TypeScript, Vite | Node.js 20+ / 24 LTS, Vite 8, React 19 | 原生 Fetch API, Server-Sent Events (SSE), Vanilla CSS 设计系统 |

---

## 2. 快速启动指南

### 2.1 启动 Go 后端

后端编译可执行文件已包含或通过源码直接运行：

```bash
cd backend

# 安装依赖并运行（默认监听所有网卡 :8080，数据保存在 data/issues.db）
go run ./cmd/server

# 或直接运行已编译好的二进制
./bin/server.exe
```

服务启动后，控制台会自动打印本机在局域网中的可用 IP 地址，例如：
```text
服务已启动 :8080，数据库 data/issues.db
  局域网地址（WLAN）: http://192.168.1.105:8080
```

> **运行测试**：在 `backend` 目录下执行 `go test -v ./...` 可运行针对健康检查、数据校验、CRUD、重启持久化及 CORS 预检的自动化测试。

---

### 2.2 启动 React 管理端

```bash
cd admin-web

# 安装依赖
npm install

# 启动开发服务器（支持局域网访问）
npm run dev
```

浏览器打开控制台输出的地址（如 `http://localhost:5173` 或同局域网 `http://<电脑IP>:5173`）。
- 管理端已内建断网/服务离线兜底拦截，后端未启动时会显示醒目的警告横幅并保留本地历史缓存，**绝不白屏**。
- 支持 **SSE (Server-Sent Events) 实时推送**：手机端一旦提交问题，无需手动刷新网页，管理台列表和俯视图均实时毫秒级高亮闪烁新增。

### 2.3 Unity 真机运行与后端地址配置

#### 在真机（Samsung Galaxy S23 Ultra 等）上运行步骤：
1. 打开 **Unity Hub**，添加并打开 `unity-ar-client` 目录。
2. 在 **File -> Build Settings** 中切换平台为 **Android**：
   - Texture Compression 保持默认或 ETC2；
   - 勾选或确认已安装 Android Build Support。
3. 进入 **Project Settings -> XR Plug-in Management**，在 Android 标签页下勾选 **Google ARCore**。
4. **一键生成场景（推荐）**：在 Unity 顶部菜单栏点击 **「Tools -> 巡检系统 -> 一键自动创建并配置 AR 场景」**。
   - 工具会自动建立 `Assets/Scenes/MainARScene.unity`，配置好 ARSession、水平平面检测、HUD 顶部栏、网络设置面板与表单，并自动完成所有脚本引用关联与 Build Settings 注册。
5. 手机开启「开发者选项」与「USB 调试」，用数据线连接电脑。
6. 点击 **Build And Run**，将 APK 直接安装并启动于手机。

#### ⭐ Unity 真机如何配置 Go 后端地址：
我们设计了**真机运行时动态网络配置、实时连通性测试与后台心跳监控系统**，无需每次变动 Wi-Fi 或 IP 时重新打包：
1. **模式一：USB 数据线直连（强烈推荐，永不掉线）**
   - 手机插上 USB 数据线连接电脑；
   - 电脑执行端口反向映射（已自动激活）：`adb reverse tcp:8080 tcp:8080`；
   - 在手机 App 的【设置】中直接点击 **「填入 USB (127.0.0.1)」** 按钮；
   - 点击测试连接，延迟低至 1~5ms，完全不受 Wi-Fi 信号、路由器隔离或防火墙限制！
2. **模式二：局域网 Wi-Fi 模式**
   - 确保手机与电脑连接在**同一个 Wi-Fi**（或手机开热点给电脑连接）；
   - 在电脑终端运行 `ipconfig` 查看电脑当前的无线局域网 IPv4 地址（如 `192.168.31.6`）；
   - 打开手机 App 点击顶部 **「⚙ 设置」** 或直接点击状态胶囊，输入 `http://<电脑IPv4>:8080`（或点击「填入 Wi-Fi」快捷键）；
   - 点击 **「测试连接」** 查看延迟与数据库状态。
3. **全自动心跳与首页胶囊双向联动**：
   - 点击「保存」后，系统自动发起连接校验；若连通则显示绿色 **「后端正常」**，若无法连接或 IP 填写错误则立刻变为红色 **「后端离线」**；
   - 客户端后台每 6 秒执行一次轻量心跳监测，服务异常退出或网络断开时，首页状态胶囊毫秒级响应变色。

## 3. 接口规范 (API Reference)

三端采用完全统一的字段名称：

| 接口 | 方法 | 说明 |
| :--- | :--- | :--- |
| `/api/health` | `GET` | 检查后端运行状态、数据库连通性、当前问题总数与启动时长 |
| `/api/issues` | `GET` | 获取问题列表，支持 `?status=` 和 `?priority=` 筛选参数 |
| `/api/issues` | `POST` | 上报新问题，后端自动生成 UUID、当前时间戳，状态默认 `open` |
| `/api/issues/{id}` | `GET` | 按 ID 查询单条问题详情 |
| `/api/issues/{id}/status` | `PATCH` | 修改处理状态（可选：`open`, `in_progress`, `resolved`） |
| `/api/issues/{id}` | `DELETE` | 删除问题记录（管理端拓展操作） |
| `/api/events` | `GET` | SSE 实时事件流，长连接自动广播数据增删改事件 |

## 4. 完成情况与加分项清单

### 4.1 必做功能完成度
- [x] **Unity AR 真实环境检测**：使用 AR Foundation 检测真实物理水平平面；
- [x] **点击放置标记**：点击水平平面命中位置生成 3D 立体标记；
- [x] **问题填写与验证**：标题必填验证（空标题拦截）、描述可选、三级优先级（low/medium/high）、三维坐标自动填充；
- [x] **提交反馈**：提供平滑动画的成功 / 失败 Toast 消息反馈；
- [x] **UI 防穿透拦截**：多层 GraphicRaycaster 与 EventSystem 拦截，点击按钮或输入框绝不误触放置标记；
- [x] **Go 后端服务**：健康检查、数据校验（标题为空、枚举错误返回明确参数提示）、SQLite 持久化、服务重启后数据保持；
- [x] **统一数据模型**：三端命名完全一致，自动生成 UUID 与 UTC 时间戳；
- [x] **React 现代管理台**：列表查看、状态原地快速修改（带乐观更新与回滚）、后端离线友好错误屏。

### 4.2 鼓励加分项实现
1. **实时通信 (Server-Sent Events, SSE)**：Go 后端内建非阻塞广播中心，手机端一提交，React 管理端无需刷新立即感知并高亮动画插入新数据。
2. **AR 标记二维俯视雷达 (PositionMap)**：React 端利用 SVG 将所有空间标记投影到 X/Z 水平面雷达上，直观展示相对分布，支持悬停互动与筛选联动。
3. **根据优先级/状态动态改变标记样式**：高/中/低优先级对应红/黄/灰不同色系，状态完成时自动切换翡翠绿，且文字带有 Billboard 始终面朝相机。
4. **移动端真机动态 IP 配置与测试**：内置设置面板直接 Ping `/api/health`，解决跨 Wi-Fi 测试频繁改代码的痛点。
5. **Unity 移动端历史记录抽屉**：巡检人员可在手机上随时调出已上报的问题列表，查看状态并联动定位。
6. **自动化单元测试与健壮性**：Go 包含全面的接口与持久化回归测试用例。

## 5. 已知问题与说明

1. **会话空间局部坐标定位**：
   - 遵照任务书第 4 节说明（*“不要求应用重启后，把历史标记恢复到完全相同的真实物理位置”*），AR 会话使用的是设备重置时的局部相对坐标系。
   - 若未来需要多次进入同一现场恢复完全相同的物理定位，可接入 ARCore Cloud Anchors 或空间二维码/物理参考物校准方案。
2. **局域网防火墙阻断**：
   - 在真机调试时，若手机测试连接提示超时，通常为 Windows Defender 防火墙拦截了 `8080` 端口入站连接。只需在 Windows 防火墙中允许 Go 程序入站或临时放行 8080 端口即可。
